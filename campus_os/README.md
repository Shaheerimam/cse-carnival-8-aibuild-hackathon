# 🎓 CampusOS — AI-Powered University Platform

> Built for **CSE Carnival 8 · AIBuild Hackathon**

---

## 📖 Project Overview

CampusOS is a Flutter-based mobile and web application that acts as a unified smart campus operating system for university students. It aggregates class schedules, room availability, campus events, announcements, and assignment deadlines into a single dashboard — and supercharges everything with a conversational AI agent. The agent (powered by **Gemini via Firebase AI**) understands natural language, calls structured tools to query and mutate live Firestore data, and can search rooms, check availability, create bookings, and cancel reservations — all through plain chat. On first launch the app seeds its five Firestore collections (`schedules`, `rooms`, `events`, `announcements`, `assignments`) from bundled JSON assets, so the experience works immediately out of the box without any manual database setup.

## ⚙️ Setup Instructions

### Prerequisites

- Flutter SDK `^3.12.2` — [install guide](https://docs.flutter.dev/get-started/install)
- Dart SDK (bundled with Flutter)
- A Firebase project — this repo is wired to `campusos-hackathon-766f0`
- (Optional) Firebase CLI for token management

### 1 · Clone the repository

```bash
git clone https://github.com/<your-org>/cse-carnival-8-aibuild-hackathon.git
cd cse-carnival-8-aibuild-hackathon/campus_os
```

### 2 · Install dependencies

```bash
flutter pub get
```

### 3 · Configure environment variables

Copy the example env file and fill in your values:

```bash
cp .env.example .env
```

> **Note:** The app reads `FIREBASE_APPCHECK_DEBUG_TOKEN` via `--dart-define` at build/run time (see below). There is no runtime `.env` loader — set values as `--dart-define` flags or via your IDE's launch configuration.

### 4 · Register the App Check debug token

Before running in debug mode you **must** register your debug token in the Firebase Console:

```
https://console.firebase.google.com/project/campusos-hackathon-766f0/appcheck/apps
```

Or via the Firebase CLI:

```bash
firebase appcheck:debugtokens:create <YOUR_TOKEN> \
  --project campusos-hackathon-766f0 \
  --app 1:263099468650:web:438f300b1aa5de58167313
```

### 5 · Run the app

**Web (recommended for development):**

```bash
flutter run -d chrome \
  --dart-define=FIREBASE_APPCHECK_DEBUG_TOKEN=<your-debug-token>
```

**Android:**

```bash
flutter run -d <device-id> \
  --dart-define=FIREBASE_APPCHECK_DEBUG_TOKEN=<your-debug-token>
```

**List available devices:**

```bash
flutter devices
```

> ℹ️ A `defaultValue` for the debug token is already embedded in `lib/main.dart` for convenience during development. Remove it before shipping to production.

### 6 · Build for production (web)

```bash
flutter build web
```

## 🔐 Environment Variables

Copy `.env.example` to `.env` **and never commit the real file**.

```dotenv
# .env.example

# Firebase App Check debug token (register at Firebase Console before use)
# Only required in debug / development builds.
# Pass as: flutter run --dart-define=FIREBASE_APPCHECK_DEBUG_TOKEN=<value>
FIREBASE_APPCHECK_DEBUG_TOKEN=your-debug-token-here
```

All Firebase project identifiers (`apiKey`, `appId`, `projectId`, etc.) live in
`lib/firebase_options.dart` which is generated by the FlutterFire CLI and is safe
to commit for open-source projects. **Do not commit real App Check debug tokens or
any service-account private keys.**

| Variable | Required | Description |
|---|---|---|
| `FIREBASE_APPCHECK_DEBUG_TOKEN` | Debug only | UUID token registered in Firebase App Check. Allows the app to pass App Check enforcement locally without a real attestation provider. |

## 🤖 How to Use the Agent

Open the **CampusOS Agent** tab (chat icon in the bottom navigation bar) and type any natural language question. The agent uses Gemini function-calling to query and update live Firestore data in real time.

### What you can ask

| Category | Example prompts |
|---|---|
| **Schedule** | `"When is my next class?"` · `"What do I have on Thursday?"` |
| **Assignments** | `"What assignments are due this week?"` · `"Show me all pending work"` |
| **Room search** | `"Find a lab on floor 7 with at least 30 seats"` · `"Is room 7A02 free tomorrow at 2 PM?"` |
| **Room booking** | `"Book room 7A02 on 2026-09-10 from 14:00 to 16:00 for a group study session"` |
| **Cancel booking** | `"Cancel my booking in room 7A02 on 2026-09-10 at 14:00"` |
| **Events** | `"I'm free until 2 PM — is there anything on campus I could drop into?"` |
| **Announcements** | `"Show me all high-priority announcements"` |

### Tips

- Be specific with **dates** (`YYYY-MM-DD`) and **times** (`HH:mm`) when booking rooms.
- If you omit required details the agent will ask clarifying questions before acting.
- The agent never claims a booking succeeded unless the Firestore write actually completed.
- Use the **quick-chip suggestions** at the top of the chat screen for one-tap prompts.

## 🔒 Security Notes

- **Anonymous Auth** is used so the app works without user sign-up while still scoping Firestore security rules to authenticated sessions.
- **App Check** enforces that only the genuine app binary can call Firebase APIs. The debug provider is only acceptable during development — switch to `ReCaptchaV3Provider` (web) or `PlayIntegrityProvider` (Android) for production.
- Revoke and delete the debug token when you finish the hackathon:

```bash
firebase appcheck:debugtokens:delete <token> \
  --project campusos-hackathon-766f0 \
  --app 1:263099468650:web:438f300b1aa5de58167313
```
